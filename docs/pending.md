## Make transfers faster (to do)
- [ ] One real measurement so far: a 2.1 GB file took about 4-5 minutes (roughly 7-9 MB/s), well below what a good Wi-Fi link can do. Find out where the time goes before changing anything:
      run **Diagnostics -> Network speed test** on the phone and `bolt linktest`, then read **Last transfer** (net / disk / hash / sync) after a big send. See docs/performance.md.
      Link test slow too -> Wi-Fi/path (5 GHz band, distance to the router). Link test fast but transfer slow -> storage or CPU.
- [ ] Known suspects, in order: the Android UDP receive buffer is only 512 KiB (the core asks for 8 MiB); Wi-Fi power-saving on the phone; Cubic vs BBR congestion control (BBR is the default now); the extra copy from app storage into Downloads on Android; one stream at a time for many small files (see parallel streams below).

      the ring stays put with "Paused", and the button becomes Resume, which continues from the partial file. Today only Cancel exists, and
      resume happens only through Retry after a cancel or failure. Useful for big files, low battery, or freeing the Wi-Fi or hotspot data for a while.
      The engine can already resume from a partial file; what is missing is the pause itself (hold the stream or close it and restart) and the UI.

- [ ] Code signing, auto-update.
- [ ] Per-IP rate limiting (pairing already locks after 3 bad proofs); DPAPI / Android Keystore protection of the private key.

- [ ] **No-router mode (Wi-Fi Direct / phone-created network)**, an extra way to connect, not a replacement. Today Bolt is direct
      transfer over the local network ("LAN mode": both devices on the same Wi-Fi or one on the other's hotspot, mDNS or typed `IP:port`
      discovery, QUIC + TLS 1.3). No-router mode would add a "Connect without Wi-Fi" step before discovery: the phone creates a private
      network (Android `LocalOnlyHotspot`, or `WifiP2pManager` as group owner), shows its name and password as a QR code or link, the laptop
      joins it (Windows WLAN API; the laptop loses its internet while joined, so warn), then Bolt connects to the phone's gateway address and
      the normal pairing and transfer run unchanged. True Windows-to-Android Wi-Fi Direct negotiation is unreliable, so the phone-created
      network is the plan. Needs real devices to test; the emulator cannot.
